# AGENTS.md

Guidance for AI coding agents working in this repository. The catalogue of
reusable workflows and their cross-repo contracts is in
[ci-templates.md](ci-templates.md); per-workflow inputs/secrets/outputs are in
the generated pages under `workflows/`; local setup, linting, and testing are
in [DEVELOPMENT.md](DEVELOPMENT.md).

## What this repo is

A library of reusable GitHub Actions workflows consumed by the other repos.

| Layout | Role |
|---|---|
| `.github/workflows/*.yml` with `workflow_call` | The public surface, called as `uses: tnoff/github-workflows/.github/workflows/<file>@<sha>` |
| `docs/workflows/*.md` | Generated by `actdocs` from each `workflow_call` file's inputs/secrets/outputs -- never hand-edit, see DEVELOPMENT.md |
| `renovate/*.json` | Shared Renovate presets |
| `self-*.yml`, `fleet-mirror.yml`, `notify-failure.yml`, `startup-failure-sweep.yml` | Not part of the library: this repo's own CI, and fleet-level automation (see ci-templates.md) |

It hosts no consumer-side pipeline. GitHub is canonical; the GitLab copy is a
read-only mirror refreshed by `fleet-mirror.yml` and runs no CI. Do not
reintroduce a GitLab CI surface.

## Non-obvious rules to honour

### Consumers pin by commit SHA -- preserve backwards compatibility

Consumers pin a full SHA (Renovate bumps it); there are no floating major
tags, only `v0.0.N` release tags. Any change that alters the inputs, secrets,
outputs, or behaviour of an existing workflow can break consumers as soon as
their pin moves, and a caller/callee contract mismatch fails at startup with
no visible check. So:

- Additive changes (new optional input with a default, doc-only) are safe.
- Renaming or removing an input/secret, or making one required, is breaking:
  ship it as a new workflow file, or rename and re-pin consumers in the same
  commit. Run `check-workflow-contracts` in consumers.
- Write real `description` fields on every input/secret/output; they are the
  source of the generated reference pages.

### Image tags

`docker-push.yml` pushes `latest` (or `tag_override`) plus an immutable
7-character short-SHA tag (`<override>-<sha>` when overriding), from one
invocation so both point at the same digest. `ocir-push.yml` is the legacy
variant: it tags the commit SHA and, only with `tag_version`, the `VERSION`
file value and `latest`. Downstream manifests in `docker-apps` pin by SHA;
its `conftest` policy rejects `latest`.

### VERSION file

`VERSION` is the single source of truth for versions: `MAJOR.MINOR.PATCH`, no
`v` prefix, no trailing whitespace. `bump-version.yml` increments it on PRs and
`tag.yml` tags it (this repo's `self-tag.yml` does that for itself).

### Pre-commit + actionlint are the gate

Every PR runs pre-commit (actionlint, shellcheck via actionlint, SHA-pin
check, doc generation). Don't bypass hooks; fix the file or the hook config.
